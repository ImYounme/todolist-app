## 1. 프로젝트 개요

### 1.1 목적

TodoList는 개인 사용자가 할일을 체계적으로 관리할 수 있도록 설계된 할일 관리 애플리케이션이다. 기존 일정 관리 도구의 한계인 카테고리 분류 부재와 종료 시간 표현 미흡 문제를 해결하여, 사용자가 자신의 업무와 일상을 효과적으로 추적하고 완수할 수 있도록 지원한다.

### 1.2 범위

| 구분 | 내용 |
|------|------|
| 포함 범위 | 사용자 인증(회원가입/로그인), 할일 CRUD, 카테고리 관리, 할일 상태 조회 및 필터링 |
| 제외 범위 | 팀 협업, 외부 캘린더 연동, 알림/푸시, 파일 첨부 |
| 사용 대상 | 개인 사용자 (인증된 회원에 한함) |

## 2. 핵심 도메인 개념

### 2.1 엔티티 정의

#### 사용자 (User)
애플리케이션에 회원가입하여 인증된 개인. 모든 데이터는 사용자 단위로 격리되며, 인증 없이는 어떠한 기능도 접근할 수 없다.

| 속성 | 설명 |
|------|------|
| 사용자 ID | 시스템 내 고유 식별자 |
| 이메일 | 로그인 및 계정 식별에 사용되는 고유 값 |
| 비밀번호 | 암호화 저장되는 인증 수단 |
| 가입일시 | 계정 생성 시각 |

#### 할일 (Todo)
사용자가 완수해야 할 단일 작업 단위. 카테고리와 연결되며 상태와 종료일을 가진다.

| 속성 | 설명 |
|------|------|
| 할일 ID | 시스템 내 고유 식별자 |
| 제목 | 할일의 이름 (필수, 최대 100자) |
| 설명 | 할일의 상세 내용 (선택) |
| 상태 | 할일의 현재 진행 상태 |
| 종료일 | 할일을 완료해야 하는 목표 날짜 (선택) |
| 카테고리 | 할일이 속한 분류 |
| 생성일시 | 할일이 등록된 시각 |
| 완료일시 | 할일이 완료 처리된 시각 |

#### 카테고리 (Category)
사용자가 직접 생성하고 관리하는 할일 분류 단위. 사용자별로 독립적으로 관리된다.

| 속성 | 설명 |
|------|------|
| 카테고리 ID | 시스템 내 고유 식별자 |
| 이름 | 카테고리 명칭 (사용자 내 고유, 최대 20자) |
| 생성일시 | 카테고리가 생성된 시각 |

### 2.2 핵심 용어 정의

| 용어 | 정의 |
|------|------|
| 할일 상태 | 할일의 진행 상황을 나타내는 값으로 `진행 중`, `완료` 두 가지를 가진다 |
| 기한 초과 | 종료일이 설정된 할일 중 현재 날짜가 종료일을 지났으나 완료되지 않은 상태 |
| 완료 | 사용자가 명시적으로 완료 처리한 할일 상태 |
| 진행 중 | 아직 완료 처리되지 않은 할일의 기본 상태 |
| 인증 세션 | 로그인 성공 후 사용자에게 발급되는 유효한 접근 권한 |

## 3. 도메인 규칙

### 3.1 사용자 인증 규칙

- **DR-AUTH-001:** 모든 사용자는 회원가입 후 로그인을 통해 인증 세션을 획득해야 한다.
- **DR-AUTH-002:** 인증되지 않은 사용자는 할일 및 카테고리 관련 모든 기능에 접근할 수 없다.
- **DR-AUTH-003:** 이메일은 시스템 전체에서 고유해야 하며, 중복 가입을 허용하지 않는다.
- **DR-AUTH-004:** 비밀번호는 평문으로 저장되지 않으며 반드시 암호화하여 보관한다.

### 3.2 할일 관리 규칙

- **DR-TODO-001:** 할일은 반드시 특정 사용자에게 귀속되며, 다른 사용자는 접근할 수 없다.
- **DR-TODO-002:** 할일의 제목은 필수 입력값이며, 최대 100자 이내로 제한한다.
- **DR-TODO-003:** 할일의 초기 상태는 `진행 중`이다.
- **DR-TODO-004:** 종료일이 설정된 할일은 현재 날짜 기준으로 기한 초과 여부를 판단한다.
- **DR-TODO-005:** 완료된 할일은 기한 초과 할일로 분류되지 않는다.
- **DR-TODO-006:** 사용자는 자신이 생성한 할일만 수정 및 삭제할 수 있다.

### 3.3 카테고리 관리 규칙

- **DR-CAT-001:** 카테고리는 사용자별로 독립적으로 관리되며, 동일한 이름의 카테고리를 동일 사용자가 중복 생성할 수 없다. (사용자당 최대 20개까지 생성 가능)
- **DR-CAT-002:** 사용자는 카테고리를 자유롭게 추가, 수정, 삭제할 수 있다.
- **DR-CAT-003:** 카테고리를 삭제할 경우, 해당 카테고리에 속한 할일은 '카테고리 미지정' 상태로 자동 전환된다.
- **DR-CAT-004:** 할일은 카테고리 없이도 생성할 수 있다.

### 3.4 조회 및 필터링 규칙

- **DR-FILTER-001:** 사용자는 카테고리 기준으로 할일을 필터링하여 조회할 수 있다.
- **DR-FILTER-002:** 사용자는 할일을 상태(`진행 중`, `완료`) 기준으로 구분하여 조회할 수 있다.
- **DR-FILTER-003:** 사용자는 기한 초과 할일을 별도로 조회할 수 있다.
- **DR-FILTER-004:** 조회 결과는 항상 해당 사용자의 데이터만 포함한다.

## 4. 주요 유스케이스

### UC-01: 회원가입
- **목표:** 시스템에 새 계정을 생성한다.
- **관련 규칙:** DR-AUTH-001, DR-AUTH-003, DR-AUTH-004
- **기본 흐름:** 이메일, 비밀번호 입력 → 이메일 중복 검증 → 비밀번호 암호화 저장 → 계정 생성 완료

### UC-02: 로그인
- **목표:** 인증 세션을 획득하여 애플리케이션 기능을 이용한다.
- **관련 규칙:** DR-AUTH-001, DR-AUTH-002
- **기본 흐름:** 이메일, 비밀번호 입력 → 자격증명 검증 → 인증 세션 발급

### UC-03: 할일 등록
- **목표:** 새로운 할일을 생성한다.
- **관련 규칙:** DR-TODO-001, DR-TODO-002, DR-TODO-003
- **기본 흐름:** 제목 입력 (설명, 종료일, 카테고리 선택 입력) → 할일 저장 → 상태 `진행 중`으로 초기화

### UC-04: 할일 상태 변경
- **목표:** 할일을 완료 처리하거나 진행 중으로 되돌린다.
- **관련 규칙:** DR-TODO-005, DR-TODO-006
- **기본 흐름:** 할일 선택 → 상태 변경 요청 → 완료일시 기록(완료 시) 또는 완료일시 초기화(재개 시)

### UC-05: 할일 조회 및 필터링
- **목표:** 원하는 조건으로 할일 목록을 확인한다.
- **관련 규칙:** DR-FILTER-001, DR-FILTER-002, DR-FILTER-003, DR-FILTER-004
- **기본 흐름:** 필터 조건 선택(카테고리 / 상태 / 기한 초과) → 조건에 맞는 할일 목록 표시

### UC-06: 카테고리 관리
- **목표:** 할일 분류를 위한 카테고리를 추가, 수정, 삭제한다.
- **관련 규칙:** DR-CAT-001, DR-CAT-002, DR-CAT-003
- **기본 흐름:** 카테고리 이름 입력 → 중복 검증 → 저장

### UC-07: 할일 수정 및 삭제
- **목표:** 기존 할일의 내용을 변경하거나 삭제한다.
- **관련 규칙:** DR-TODO-006
- **기본 흐름:** 할일 선택 → 내용 수정 또는 삭제 요청 → 소유권 검증 → 처리 완료

## 5. 도메인 경계 (Bounded Context)

### 5.1 컨텍스트 맵

```
+---------------------+       +---------------------+
|    인증 컨텍스트      |       |   할일 관리 컨텍스트   |
|  (Auth Context)     |       |  (Todo Context)     |
|                     |       |                     |
|  - 회원가입          |  인증  |  - 할일 CRUD         |
|  - 로그인            +------>|  - 상태 관리          |
|  - 인증 세션 관리     |  세션  |  - 기한 초과 판단     |
|                     |       |  - 필터링 조회         |
+---------------------+       +----------+----------+
                                          |
                                     카테고리 참조
                                          |
                              +----------v----------+
                              |  카테고리 관리 컨텍스트 |
                              | (Category Context)  |
                              |                     |
                              |  - 카테고리 CRUD      |
                              |  - 사용자별 독립 관리  |
                              +---------------------+
```

### 5.2 컨텍스트 설명

| 컨텍스트 | 책임 | 핵심 개념 |
|---------|------|---------|
| 인증 (Auth) | 사용자 신원 확인 및 세션 관리 | 사용자, 인증 세션 |
| 할일 관리 (Todo) | 할일의 생명주기 및 상태 관리 | 할일, 상태, 기한 초과 |
| 카테고리 관리 (Category) | 사용자 정의 분류 체계 관리 | 카테고리 |

### 5.3 컨텍스트 간 의존 관계

- **할일 관리 → 인증:** 모든 할일 작업은 유효한 인증 세션을 필요로 한다.
- **할일 관리 → 카테고리 관리:** 할일은 카테고리를 참조하지만, 카테고리 없이도 독립적으로 존재할 수 있다.
- **카테고리 관리 → 인증:** 카테고리 작업은 유효한 인증 세션을 필요로 하며, 사용자 단위로 격리된다.
