## 1. 시나리오 개요

### 1.1 목적

본 문서는 TodoList 애플리케이션의 주요 사용 흐름을 페르소나 기반 시나리오로 정의한다. 정상 흐름 시나리오 7개와 예외/경계 시나리오 4개로 구성되며, 각 시나리오는 기능 요구사항(FR)과 직접 연결되어 요구사항 추적 및 테스트 근거로 활용된다.

### 1.2 페르소나 정의

| 페르소나 | 이름 | 유형 | 주요 목표 |
|----------|------|------|-----------|
| 페르소나 A | 김철수 | 20대 직장인 | 업무/개인 할일 통합 관리, 마감일 누락 방지 |
| 페르소나 B | 박소영 | 30대 가정주부 | 가사/육아/개인 일정 카테고리 기반 체계 관리 |
| 미인증 사용자 | — | 비회원 | 예외 시나리오 검증 목적 |

### 1.3 시나리오 목록 인덱스

| 시나리오 ID | 유형 | 페르소나 | 시나리오명 | 관련 FR |

| SC-01 | 정상 흐름 | 김철수 | 신규 사용자 회원가입 | FR-AUTH-001, FR-AUTH-002, FR-AUTH-003 |
| SC-02 | 정상 흐름 | 김철수 | 로그인 및 로그아웃 | FR-AUTH-004, FR-AUTH-005, FR-AUTH-006 |
| SC-03 | 정상 흐름 | 김철수 | 카테고리 생성 및 할일 등록 | FR-CAT-001, FR-CAT-007, FR-TODO-001, FR-TODO-002 |
| SC-04 | 정상 흐름 | 박소영 | 할일 완료 처리 | FR-TODO-008, FR-TODO-009, FR-TODO-010 |
| SC-05 | 정상 흐름 | 박소영 | 카테고리 필터링으로 할일 조회 | FR-FILTER-001, FR-FILTER-002, FR-FILTER-003, FR-FILTER-004 |
| SC-06 | 정상 흐름 | 김철수 | 기한 초과 할일 확인 및 수정 | FR-FILTER-003, FR-TODO-005, FR-TODO-010 |
| SC-07 | 정상 흐름 | 박소영 | 카테고리 삭제 및 소속 할일 미지정 전환 확인 | FR-CAT-005, FR-CAT-006 |
| SC-08 | 예외/경계 | 미인증 사용자 | 중복 이메일로 회원가입 시도 | FR-AUTH-002 |
| SC-09 | 예외/경계 | 미인증 사용자 | 미인증 상태로 할일 접근 시도 | FR-AUTH-005 |
| SC-10 | 예외/경계 | 김철수 | 할일 제목 100자 초과 입력 시도 | FR-TODO-003 |
| SC-11 | 예외/경계 | 박소영 | 카테고리 20개 한도 초과 시도 | FR-CAT-003 |

## 2. 시나리오 상세

### 정상 흐름 시나리오

---

### SC-01: 신규 사용자 회원가입

- **페르소나:** 김철수
- **사전 조건:** 김철수는 TodoList 애플리케이션에 계정이 없는 신규 방문자이다. 브라우저에서 서비스 URL에 접속한 상태이다.
- **목표:** 이메일과 비밀번호를 사용하여 새 계정을 생성하고, 서비스 이용 준비를 완료한다.
- **관련 요구사항:** FR-AUTH-001, FR-AUTH-002, FR-AUTH-003

**시나리오 흐름:**

| 단계 | 사용자 행동 | 시스템 응답 | 관련 화면 |
|------|-------------|-------------|-----------|
| 1 | 로그인 화면에서 "회원가입" 링크를 클릭한다. | 회원가입 화면으로 이동한다. | SCR-02 → SCR-01 |
| 2 | 이메일 입력 필드에 `cheolsu.kim@example.com`을 입력한다. | 이메일 형식 유효성을 실시간으로 검증한다. | SCR-01 |
| 3 | 비밀번호 입력 필드에 비밀번호를 입력한다. | 비밀번호 입력값을 마스킹하여 표시한다. | SCR-01 |
| 4 | "회원가입" 버튼을 클릭한다. | 이메일 중복 여부를 서버에서 검증한다. 중복이 없으면 비밀번호를 암호화(bcrypt)하여 저장하고 계정을 생성한다. | SCR-01 |
| 5 | — | 회원가입 성공 메시지를 표시하고 로그인 화면으로 이동한다. | SCR-01 → SCR-02 |

**사후 조건:**
- 김철수의 계정(`cheolsu.kim@example.com`)이 시스템에 생성된다.
- 비밀번호는 평문이 아닌 암호화된 형태로 데이터베이스에 저장된다.
- 김철수는 로그인 화면으로 이동하며 즉시 로그인할 수 있는 상태가 된다.

**비고:**
- 이메일 중복 시 오류 처리는 SC-08에서 별도 검증한다.
- 비밀번호 복잡도 정책은 OQ-004 미결 사항으로, Phase 1에서 정책 확정 후 반영한다.

---

### SC-02: 로그인 및 로그아웃

- **페르소나:** 김철수
- **사전 조건:** 김철수는 SC-01을 통해 계정(`cheolsu.kim@example.com`)을 생성한 상태이다. 로그인 화면에 접속해 있다.
- **목표:** 이메일과 비밀번호로 로그인하여 서비스를 이용하고, 사용 완료 후 로그아웃한다.
- **관련 요구사항:** FR-AUTH-004, FR-AUTH-005, FR-AUTH-006

**시나리오 흐름:**

| 단계 | 사용자 행동 | 시스템 응답 | 관련 화면 |
|------|-------------|-------------|-----------|
| 1 | 이메일 필드에 `cheolsu.kim@example.com`, 비밀번호 필드에 비밀번호를 입력한다. | 입력값을 실시간으로 표시한다(비밀번호는 마스킹). | SCR-02 |
| 2 | "로그인" 버튼을 클릭한다. | 자격증명을 서버에서 검증하고, 일치 시 JWT 토큰(HS-512)을 발급하여 클라이언트에 저장한다. | SCR-02 |
| 3 | — | 로그인 성공 후 할일 목록 화면으로 이동한다. | SCR-02 → SCR-03 |
| 4 | 할일 목록 화면에서 서비스를 이용한다. | 모든 API 요청 시 JWT 토큰을 검증하여 인증 상태를 확인한다. | SCR-03 |
| 5 | 사용자 정보 화면 또는 메뉴에서 "로그아웃" 버튼을 클릭한다. | 클라이언트 측 JWT 토큰을 제거한다. | SCR-07 |
| 6 | — | 로그아웃 완료 후 로그인 화면으로 이동한다. | SCR-02 |

**사후 조건:**
- 로그인 성공 시 JWT 토큰이 클라이언트에 저장되어 인증 세션이 유지된다.
- 로그아웃 완료 시 클라이언트의 JWT 토큰이 제거되어 인증 세션이 종료된다.
- 로그아웃 이후 토큰 없이 보호된 API에 접근하면 401 응답을 반환한다.

**비고:**
- JWT 토큰 만료 시간은 OQ-001 미결 사항이다.
- Refresh Token 전략은 OQ-002 미결 사항으로 Phase 1에서는 미적용을 가정한다.

### SC-03: 카테고리 생성 및 할일 등록

- **페르소나:** 김철수
- **사전 조건:** 김철수는 로그인된 상태이다. 카테고리가 없고 등록된 할일도 없다.
- **목표:** 업무와 개인 카테고리를 각각 생성하고, 각 카테고리에 할일을 등록하여 업무와 개인 할일을 분리 관리한다.
- **관련 요구사항:** FR-CAT-001, FR-CAT-002, FR-CAT-007, FR-TODO-001, FR-TODO-002, FR-TODO-003

**시나리오 흐름:**

| 단계 | 사용자 행동 | 시스템 응답 | 관련 화면 |
|------|-------------|-------------|-----------|
| 1 | 할일 목록 화면에서 "카테고리 관리" 메뉴를 클릭한다. | 카테고리 관리 화면(모달/페이지)이 열린다. | SCR-03 → SCR-06 |
| 2 | 카테고리 이름 입력 필드에 `업무`를 입력하고 추가 버튼을 클릭한다. | 중복 여부를 검증하고 `업무` 카테고리를 생성한다. 카테고리 목록에 `업무`가 표시된다. | SCR-06 |
| 3 | 카테고리 이름 입력 필드에 `개인`을 입력하고 추가 버튼을 클릭한다. | 중복 여부를 검증하고 `개인` 카테고리를 생성한다. 카테고리 목록에 `개인`이 표시된다. | SCR-06 |
| 4 | 카테고리 관리 화면을 닫고 할일 목록 화면으로 돌아온다. | 할일 목록 화면이 표시된다. | SCR-03 |
| 5 | "할일 추가" 버튼을 클릭한다. | 할일 등록 화면(모달/페이지)이 열린다. | SCR-03 → SCR-04 |
| 6 | 제목에 `주간 보고서 작성`, 종료일에 `2026-04-29`, 카테고리에 `업무`를 선택하고 저장 버튼을 클릭한다. | 입력값을 검증하고 할일을 생성한다. 초기 상태는 `진행 중`으로 설정된다. | SCR-04 |
| 7 | — | 할일 목록 화면에 `주간 보고서 작성` 할일이 `진행 중` 상태로 표시된다. | SCR-03 |
| 8 | 다시 "할일 추가" 버튼을 클릭한다. | 할일 등록 화면이 열린다. | SCR-03 → SCR-04 |
| 9 | 제목에 `헬스장 등록`, 카테고리에 `개인`을 선택하고 저장 버튼을 클릭한다. (종료일 미입력) | 카테고리 없이도 저장 가능함을 확인하며 할일을 생성한다. 초기 상태는 `진행 중`으로 설정된다. | SCR-04 |
| 10 | — | 할일 목록 화면에 `헬스장 등록` 할일이 `진행 중` 상태로 표시된다. | SCR-03 |

**사후 조건:**
- `업무`, `개인` 카테고리 2개가 김철수 계정에 생성된다.
- `주간 보고서 작성` 할일이 `업무` 카테고리, 종료일 `2026-04-29`, 상태 `진행 중`으로 등록된다.
- `헬스장 등록` 할일이 `개인` 카테고리, 종료일 없음, 상태 `진행 중`으로 등록된다.

**비고:**
- 카테고리 중복 이름 생성 시 오류 처리는 FR-CAT-002에 의해 시스템이 오류 메시지를 반환한다.
- 카테고리 없이 할일 생성도 허용된다(FR-CAT-007).

### SC-04: 할일 완료 처리

- **페르소나:** 박소영
- **사전 조건:** 박소영은 로그인된 상태이다. `가사` 카테고리에 `청소기 돌리기` 할일이 `진행 중` 상태로 등록되어 있다.
- **목표:** 완료한 가사 할일을 `완료` 상태로 전환하고, 필요 시 다시 `진행 중`으로 되돌린다.
- **관련 요구사항:** FR-TODO-008, FR-TODO-009, FR-TODO-010

**시나리오 흐름:**

| 단계 | 사용자 행동 | 시스템 응답 | 관련 화면 |
|------|-------------|-------------|-----------|
| 1 | 할일 목록 화면에서 `청소기 돌리기` 할일을 확인한다. | `청소기 돌리기`가 `진행 중` 상태로 표시된다. | SCR-03 |
| 2 | `청소기 돌리기` 항목의 완료 버튼(체크박스 또는 상태 변경 버튼)을 클릭한다. | 서버에 상태 변경 요청을 전송한다. | SCR-03 |
| 3 | — | 할일 상태가 `완료`로 전환되고 현재 일시가 완료일시로 기록된다. 화면에 `완료` 상태로 표시된다. | SCR-03 |
| 4 | `청소기 돌리기` 항목을 클릭하여 상세 화면으로 이동한다. | 할일 상세 화면에 `완료` 상태와 완료일시가 표시된다. | SCR-05 |
| 5 | 상세 화면에서 "진행 중으로 되돌리기" 버튼을 클릭한다. | 서버에 상태 재개 요청을 전송한다. | SCR-05 |
| 6 | — | 할일 상태가 `진행 중`으로 전환되고 완료일시가 초기화(null)된다. | SCR-05 |
| 7 | — | 종료일이 현재 날짜보다 이전인 경우 `기한 초과` 상태로 표시된다. 종료일이 없거나 현재 날짜 이후인 경우 일반 `진행 중`으로 표시된다. | SCR-03 |

**사후 조건:**
- 최종적으로 `청소기 돌리기`는 `진행 중` 상태이며 완료일시는 null이다.
- 종료일 조건에 따라 기한 초과 여부가 재판단된다.

**비고:**
- DR-TODO-005에 따라 `완료` 상태의 할일은 기한 초과로 분류되지 않는다.
- 상태를 `진행 중`으로 되돌린 후에는 DR-TODO-004에 따라 기한 초과 여부가 즉시 재판단된다.

### SC-05: 카테고리 필터링으로 할일 조회

- **페르소나:** 박소영
- **사전 조건:** 박소영은 로그인된 상태이다. `가사`, `육아`, `개인` 카테고리가 생성되어 있고, 각 카테고리에 여러 할일이 등록되어 있다. 일부 할일은 `완료` 상태이고, 일부는 `진행 중` 상태이다.
- **목표:** 카테고리 필터와 상태 필터를 활용하여 원하는 할일만 선별 조회하고, 기한 초과 할일을 별도로 확인한다.
- **관련 요구사항:** FR-FILTER-001, FR-FILTER-002, FR-FILTER-003, FR-FILTER-004, FR-TODO-004

**시나리오 흐름:**

| 단계 | 사용자 행동 | 시스템 응답 | 관련 화면 |
|------|-------------|-------------|-----------|
| 1 | 할일 목록 화면에서 전체 할일 목록을 확인한다. | 박소영 본인의 할일만 전체 표시된다. 타 사용자 데이터는 포함되지 않는다. | SCR-03 |
| 2 | 카테고리 필터에서 `육아`를 선택한다. | `육아` 카테고리에 속한 할일만 필터링하여 표시한다. | SCR-03 |
| 3 | 상태 탭에서 `진행 중` 탭을 선택한다. | `육아` 카테고리 중 `진행 중` 상태인 할일만 표시된다. | SCR-03 |
| 4 | 상태 탭에서 `완료` 탭을 선택한다. | `육아` 카테고리 중 `완료` 상태인 할일만 표시된다. | SCR-03 |
| 5 | 카테고리 필터를 `전체`로 초기화한다. | 모든 카테고리의 할일이 다시 표시된다. | SCR-03 |

## 3. 시나리오-요구사항 추적 매트릭스
